# CLAUDE.md

This file is the AI handover guide for this repository.

Use it as the first-read context before making changes.

## 1) Project Identity

- Project: Search Guard Website
- Owner: floragunn GmbH
- Deployment model: static website build, deployed via GitLab CI to SFTP + Cloudflare cache purge
- Current architecture: **Next.js static export** + existing React Router app

## 2) Core Migration Decisions (Do Not Undo)

1. `react-snap` was replaced by Next static export.
2. SEO metadata rendering moved to `react-helmet-async` integration with Next `_document`.
3. Route prerendering is dynamic, derived from route definitions + Contentful JSON content.
4. Site output remains static (`out/`) for CDN/static hosting.
5. `/blog/page/1/` should canonicalize to `/blog/` (Cloudflare 301 recommended; static fallback page exists).
6. Custom 404 content is used via `pages/404.js` rendering the app at `/404/`.

## 3) High-Level Architecture

### Next pages layer

- `pages/[[...slug]].js`
  - Catch-all static page.
  - `getStaticPaths()` builds route list from `src/Routes.js` + Contentful slug data.
  - `getStaticProps()` passes `routePath`, `locale`, and `pageData` (via `routeDataLoader.js`) into the app shell.
  - Locale-aware: generates localized path variants for `SUPPORTED_LOCALES`.
- `pages/404.js`
  - Renders `<NextRoutesApp location="/404/" />` so static 404 uses custom NotFound UI.
- `pages/_app.js`
  - Client-side `HelmetProvider` wrapper.
  - Includes an asset-prop normalization patch for legacy asset import shapes.
  - Imports i18n config (`src/i18n/config`).
- `pages/_document.js`
  - Server-side `HelmetProvider` context extraction.
  - Injects Helmet tags into `<Head>` during static generation.
  - Metadata normalization: truncates titles (58 chars) and descriptions (150 chars), auto-derives missing OG/Twitter tags.
  - HTML `lang` attribute detection based on route (e.g. German for `/datenschutz/`, `/impressum/`).
  - Loads legacy CSS and global script assets from `/public/assets`.
  - Preload hints for fonts and Materialize CSS; cookie consent script.

### Legacy app layer (kept)

- `src/NextRoutesApp.js`
  - Uses `StaticRouter` on server/static render and `BrowserRouter` in browser.
  - Locale-aware: sets router `basename` to `/{locale}` for non-default locales.
  - Syncs i18n language and wraps in `LocaleProvider` + `PageDataProvider`.
- `src/utils/routeDataLoader.js`
  - Loads page-specific data (posts, persons, whitepapers, etc.) from JSON files at build time.
  - Used by `getStaticProps()` to pass pre-loaded data into each page.
- `src/Routes.js`
  - Main route map (React Router v5 `Switch` + `Route` + `Redirect`).
  - Includes `PrerenderReadySignal` (`window.__PRERENDER_READY__`) for legacy prerender scripts.
- `src/components/PageWrapper/PageWrapper.js`
  - Global default SEO tags (title/description/canonical/OG/Twitter).
  - Generates hreflang alternate links for localizable routes.

### Content layer

Content is fetched into JSON files under `src/Api/` and consumed at build time:
- `contentfulPosts.json`
- `contentfulPersons.json`
- `contentfulWhitepapers.json`
- plus other contentful snapshots used by components

## 5) Route Generation Details

Dynamic route discovery is implemented in:
- `pages/[[...slug]].js`
- `scripts/prerender-routes.js` (legacy helper/reporting)

Route sources:
1. Static `path="..."` values parsed from `src/Routes.js`.
2. Blog post slugs from `contentfulPosts.json`.
3. Blog category routes derived from post tags.
4. Blog pagination routes (`/blog/page/2/` and up; page 1 canonicalized to `/blog/`).

Important:
- Keep route path strings explicit in `src/Routes.js`.

## 6) SEO Model

### Meta tags

- Primary mechanism: `react-helmet-async`.
- SSR/static extraction path: `_document.js` `HelmetProvider` context.
- Page defaults: `PageWrapper` sets baseline metadata.
- Route/page components can override with their own `Helmet` usage.

### Structured data (JSON-LD)

- Prefer deterministic JSON serialization (`JSON.stringify`) for JSON-LD script payloads.
- Avoid raw string interpolation that can break with quotes/newlines.

### Sitemap

- Generated by `scripts/sitemap.js` from the output directory (`out/`).
- Excludes specific URLs (blacklist in script).
- Includes deduplication and trailing slash normalization.
- Excludes known non-canonical aliases (`/security-for-elasticsearch/`, `/elasticsearch-kibana-security/`, `/tls-certificate-generator/`, `/blog/page/1/`).

### 404 / indexability

- Custom page is generated in `out/404.html` and `out/404/index.html`.
- Hosting/CDN must be configured to serve `404.html` with HTTP 404 for unknown routes.

## 7) Redirects and Canonical Rules

- Preferred production canonical redirect handling remains Cloudflare 301 rules.
- Do not reintroduce `.htaccess` generation inside `out/` for this project.

## 8) CSS/SCSS Architecture

### Global SCSS only — no CSS Modules

Next.js forbids global CSS imports from component files (`import './Foo.scss'` will fail the build).

Styles are compiled automatically by Next.js via **`styles/main.scss`**, which is imported in `pages/_app.js`. This file uses `@use` to aggregate all component/page SCSS files. Next.js compiles it during `next build` and outputs CSS chunks in `_next/static/css/`.

When adding new styles:
1. Create the `.scss` file alongside its component (e.g. `src/views/Foo/Foo.scss`).
2. Use `@use '../../styles/Colors' as *;` and `@use '../../styles/Breakpoints' as *;` for variables.
3. Add a `@use` line to `styles/main.scss` (if the filename collides with an existing one, add `as AliasName`).
4. The styles will compile automatically on next build.

### Materialize CSS grid

Materialize is loaded globally from `/public/assets/materialize.min.css`. The grid system uses `float: left` on `.col` elements.

Common classes: `.row`, `.col .s12 .m4 .m6 .l4 .l6`, `.push-m6`, `.pull-m6`.

**Pitfall:** Materialize `.col` floats break flexbox centering. When you need centered content inside a Materialize grid column, use a wrapper `<div>` inside the `.col` and apply `text-align: center` on it. Use higher-specificity selectors (scope under a wrapper class, e.g. `.my-wrapper .my-element`) to override Materialize defaults.

### Bare element selectors are styled globally — do not use `<nav>`

Two stylesheets style bare HTML elements site-wide, so using those elements anywhere else
silently inherits site-chrome styling:

- **Materialize** styles `nav` as a navbar: dark background, fixed `height`/`line-height: 56px`,
  white links, and `float: left` on `nav ul li`.
- **`src/components/Navbar/Navbar.scss:4`** additionally styles bare `nav` with
  `background-color: $darkBlueNav` and `padding-left/right: 200px`, with further overrides in
  media queries further down the same file.

**Do not use `<nav>` for in-page navigation** (sidebars, "jump to" lists, tables of contents).
Use `<div role="navigation" aria-label="…">` instead — identical landmark semantics for
accessibility, with none of the inherited styling. Resetting the properties one by one is not
worth it: the rules are spread across several media queries and will drift.

Real example: the FAQ page "Jump to" sidebar (`src/views/Faqs/Faqs.js`) originally used `<nav>`
and rendered with a dark box behind it on desktop; on mobile the 200px side padding pushed the
list off-centre and forced every category onto three lines.

Before styling any semantic element (`nav`, `header`, `footer`, `main`, `aside`), grep for a
bare selector first:

```bash
grep -rn "^\s*nav\s*{" src styles --include="*.scss"
```

### Color schema system

Most tile/section components accept a `colorschema` prop with values `"dark"`, `"light"`, or `"white"`:
- `"dark"` → primary blue background, light text
- `"light"` → secondary-light (mint) background
- `"white"` → white background

Applied via `getColorSchemaCSS(colorschema)` and `getColorSchemaCSSForSVG(colorschema)` from `src/utils/styleUtils.js`.

### Design tokens

Colors (`src/styles/Colors.scss`):
- `$primary: #184962`, `$primary-light: #478EB3`
- `$secondary: #02F0DD`, `$secondary-light: #B0F8F2`, `$secondary-dark: #00B7A8`
- `$white`, `$black`, `$lightGrey: #E8ECED`, `$darkGrey: #63737E`

Breakpoints (`src/styles/Breakpoints.scss`):
- `$mobile: 600px`, `$tablet: 768px`, `$tabletBig: 992px`, `$xl: 1200px`

### Material Icons

Loaded globally. Use `<i className="material-icons">icon_name</i>`. Size/color modifiers: `md-96`, `md-dark`. Set explicit `font-size` in custom SCSS if `md-96` doesn't apply.

## 9) UI/JS Behavior Notes

Interactive behavior comes from a mix of React + legacy globals:

- Materialize JS is loaded globally in `_document.js`.
- Dropdown/sidenav initialization is handled in React components (e.g. `Navbar`) and legacy scripts.
- Carousel components (`TrustedBy`, `References`, `Integrators`) use `window.Glide` with guarded initialization in `useEffect`.

When fixing UI regressions:
1. Verify browser-only guards (`typeof window !== 'undefined'`).
2. Ensure instances are destroyed on unmount.
3. Check both SSR output and hydrated client behavior.

## 11) Reusable Component Catalog

All feature/product pages are built from these shared components:

- **`PageWrapper`** — Wraps every page. Includes Navbar, Footer, and default Helmet meta tags.
- **`Title`** — Hero section with `headline`, `text`, and `breadcrumb` props. Renders schema.org BreadcrumbList markup.
- **`ImageTextTile`** — Two-column section (image + text). Props: `icon`, `iconPosition` (`"left"` or `"right"`), `headline`, `text`, `colorschema`. Alternate left/right for visual rhythm.
- **`ColumnedTile`** — Multi-column card layout. Props: `columns` (array of `{headline, text, image?, button?}`), `headline`, `colorschema`. Auto-divides columns equally.
- **`TextTile`** — Centered text block with optional CTA button. Props: `headline`, `text`, `ctaText`, `link`, `colorschema`.
- **`FilledDivider`** — SVG arrow divider between sections. Props: `colorschema`.
- **`PreFooter`** — Newsletter signup section. Used at the bottom of most pages.
- **CTA variants** (`src/components/CTA/`) — Page-specific wrappers around TextTile (e.g. `CTAAlerting`, `CTACompliance`, `CTAStartFreeTrial`).

### Standard feature page structure

```
<PageWrapper>
  <Helmet> ... </Helmet>
  <Title headline="..." text="..." breadcrumb={...} />
  <ImageTextTile iconPosition="left"  colorschema="light" ... />
  <ImageTextTile iconPosition="right" colorschema="dark"  ... />
  <ImageTextTile iconPosition="left"  colorschema="light" ... />
  <FilledDivider colorschema="white" />
  {/* Custom sections (benefits, capabilities, connectors, etc.) */}
  <CTA... colorschema="white" />
  <PreFooter />
</PageWrapper>
```

Page-specific sub-components go in `src/components/<PageName>/` (e.g. `src/components/Alerting/AlertingBenefits.js`).

## 15) Frequent Failure Modes

1. Metadata missing in static HTML:
   - Usually Helmet provider/context wiring regression.
   - Check `_document.js` and `_app.js` integration.
2. Route missing from static export:
   - Usually not discoverable by `getStaticPaths()` route generation logic.
   - Ensure `path="..."` exists in `src/Routes.js` or content JSON contains slug.
3. Hydration mismatch:
   - Caused by non-deterministic render output or JSON-LD string rendering mismatch.
4. Carousel/dropdown not working:
   - Client init timing or missing global dependency guard.
5. `npm` registry/network issues (`ENOTFOUND`):
   - Environment/network problem, not project code.
6. Build fails with "Global CSS cannot be imported from files other than your Custom `<App>`":
   - A component is importing a `.scss` file directly. Remove the import; add the file to `styles/main.scss` instead.
7. Custom CSS not applying / Materialize overriding styles:
   - Materialize `.col` uses `float: left` and `.row` has margins that override custom styles.
   - Use higher-specificity selectors scoped under a wrapper class (e.g. `.my-wrapper .my-element`).
   - Wrap content inside `.col` divs in an inner `<div>` for independent styling.
8. Sass `@use` namespace collision:
   - If two SCSS files have the same basename (e.g. `BlogPost.scss` in different dirs), add `as AliasName` to the second `@use` in `styles/main.scss`.
9. A new component renders with unexpected dark backgrounds, huge padding, or wrongly floated list items:
   - It is probably using a bare semantic element that is styled globally — most often `<nav>`.
   - Materialize styles `nav` as a navbar, and `src/components/Navbar/Navbar.scss:4` adds
     `padding-left/right: 200px` to every `nav` on the site.
   - Use `<div role="navigation" aria-label="…">` for in-page navigation. See §8
     "Bare element selectors are styled globally".

## 19) Task Templates for AI Agents

Use these templates to execute common tasks consistently.

### A) Add a new static page route

1. Create the page/view component under `src/views/...` (or relevant existing folder).
2. If the page needs custom styles, create a `.scss` file alongside it and add a `@use` line to `styles/main.scss`.
3. If the page has reusable sub-sections, create components under `src/components/<PageName>/`.
4. Add a `<Route exact path=\"/your-path/\" ...>` entry in `src/Routes.js`.
5. If needed, add nav/footer/internal links.
6. Ensure page-level `<Helmet>` tags are set (title/description/canonical), or confirm defaults are acceptable.
7. Run:
   - `npm run build-local`
8. Verify:
   - `out/your-path/index.html` exists
   - metadata is present in prerendered HTML
   - route appears in `out/sitemap.xml` (if indexable)

### B) Add a Contentful-driven page type/slug source

1. Add/update fetch script(s) in `src/Api/` to produce required JSON snapshot.
2. Extend route discovery in:
   - `pages/[[...slug]].js` `getStaticPaths()`
   - and optionally `scripts/prerender-routes.js` (parity for legacy tooling)
3. Implement route rendering in `src/Routes.js` + corresponding component.
4. Run:
   - `npm run build` (or `npm run fetch` then `npm run build-local`)
5. Verify generated pages and sitemap entries.

### C) Add a legacy URL redirect to canonical page

Preferred: Cloudflare 301 rule.

Code-side fallback options:
1. Add a route in `src/Routes.js` using `LegacyRedirect` to canonical path.
2. Keep canonical URL tag on target page correct.
3. Run `npm run build-local` and verify redirect behavior in generated HTML.

### D) Fix missing/incorrect page metadata

1. Check page component for `<Helmet>` usage.
2. Confirm server extraction path is intact:
   - `pages/_document.js`
   - `pages/_app.js`
3. If no page-specific metadata exists, add it in the page/view component.
4. Run `npm run build-local`.
5. Verify in `out/.../index.html`:
   - `<title>`
   - `meta[name=\"description\"]`
   - canonical link
   - OG/Twitter tags as applicable

### E) Fix JSON-LD / hydration mismatch

1. Locate JSON-LD emitting component.
2. Ensure deterministic serialization (`JSON.stringify` into script content).
3. Avoid render-time differences between server and client.
4. Run:
   - `npm run start` (dev check hydration)
   - `npm run build-local` (static output check)
5. Verify no hydration warnings and valid JSON-LD in HTML.

### F) Fix carousel/dropdown/sidenav JS regressions

1. Identify component owning initialization (e.g. `Navbar`, `TrustedBy`, `References`, `Integrators`).
2. Ensure browser guards (`typeof window !== 'undefined'`).
3. Ensure third-party global exists before init (`window.M`, `window.Glide`).
4. Ensure cleanup destroys instances on unmount.
5. Verify in dev browser and after static build.

### G) Update sitemap behavior

1. Edit `scripts/sitemap.js` (blacklist, normalization, inclusion rules).
2. Run `npm run build-local` (or `npm run sitemap` after a build).
3. Validate `out/sitemap.xml`:
   - no duplicates
   - correct canonical format
   - expected route inclusion/exclusion
   - no known non-canonical alias routes

### H) Validate release-readiness after changes

1. Run:
   - `npm ci`
   - `npm run build`
2. Run checklist from `README.md` (Release Checklist section).
3. Confirm CI assumptions are still valid (`.gitlab-ci.yml` contract not broken), especially artifact gates.
